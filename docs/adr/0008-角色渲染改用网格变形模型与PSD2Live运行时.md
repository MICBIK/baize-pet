# ADR 0008: 角色渲染改用网格变形模型（PSD2Live p2lrt 运行时）

- 状态：提议（2026-11-08，待 haiden 拍板）
- 关联：演进 [ADR 0007](0007-角色渲染采用分层部件与程序动画.md)，0007 在"备选方案"里预留了"WebGL 网格变形"作为未来方向

## 背景

ADR 0007 的分层部件方案把一张平面原画切成 23 个部件。运行时让这些部件相互平移（视差）和刚性旋转。

部件一错开，就会露出原画里从来没画过的区域。第 1～7 轮都在用算法补这些像素（inpaint、外扩、手工规则），每一轮都会在某些姿势下露馅：双线、白块、泥色、黑条。审核记录见 `docs/rig-qa/`。

结论是：**从单张平面画切块再平移，结构上必然露底**。用户的要求是"最完美，不将就"，所以需要换渲染模型。

业界的通行做法（Live2D 式）有两个要点：

1. **分层原画**：每个部件单独一层，被挡住的部分也完整画出来。
2. **网格变形**：部件被拉伸、弯曲，而不是相互滑开。

Live2D Cubism、Spine、DragonBones 的运行库授权和 AGPL-3.0-only 冲突，是红线。

## 决定

1. 新增第三种渲染器 `renderer: "p2l"`，播放 PSD2Live 导出的 `.p2lrt` 网格模型。
   - 角色包 `manifest.json` 增加 `model` 字段（包内相对路径，必须是 `.p2lrt`）。
   - 动画值增加 `p2l:<片段>[@<表情>]` 形式。片段和表情可以只写一个，但不能都空。
   - 例如 `"happy": "p2l:Happy@Smile"`、`"shy": "p2l:@Shy"`。
2. 播放器使用 PSD2Live 的**网页播放器**，原样放入仓库，见 `apps/desktop/src/renderer/src/pet/vendor/p2l/`：
   - `p2l.js`：ES 模块 `P2LPlayer`，WebGL 1 绘制，约 36 KB。
   - `p2l_runtime.wasm`：Rust 运行时的 WebAssembly 构建，约 630 KB。构建时以 base64 内联进渲染进程包，因为 `file://` 页面不能 `fetch` 本地文件。
   - 运行时自带这些行为：眨眼、呼吸、视线跟随（`lookAt`）、口型（`lipSync`）、动作片段、表情、物理（头发、耳、尾）。
   - 本仓库只负责三件事：
     - 动作名到片段/表情的映射（`p2lAnimation.ts`）；
     - 说话时驱动口型；
     - 逐像素点击检测：重绘当前帧后立即 `readPixels`。
3. **许可边界**：
   - PSD2Live 仓库是混合许可。网页播放器（`:targets:web`）和运行时（`runtime/`）是 **MIT**，可以合法随 AGPL 程序分发。上游用 Gradle 依赖关系保证 MIT 模块不依赖任何 GPL 模块。
   - 编辑器本体、引擎 `umamo`、Cubism/PSD 导出是 **GPL-3.0**，只作为美术管线的**外部工具**使用，任何代码都不进仓库。
   - 第三方代码统一放在 `vendor/<名字>/` 下，必须附上游 `LICENSE` 和来源说明（`README.md`，记录 commit 与 sha256）。`scripts/check-spdx.mjs` 豁免 `vendor/` 的 AGPL 头检查，但没有 `LICENSE` 会报错。biome 忽略 `vendor/`。
   - 不导出、也不分发任何 Cubism 格式（moc3/cmo3）。
4. **CSP**：宠物窗口（`index.html`）的 `script-src` 增加 `'wasm-unsafe-eval'`，只放行 WebAssembly 编译，不放行 `eval`。聊天和设置窗口不变。
5. **美术管线**：
   - B3 的分层 PSD 由 AI 生成。可见像素取自原画，被挡区域用生图模型按洋红遮罩补画，禁止代码糊图。
   - 绑定、物理、动作在 PSD2Live 里完成，导出 `p2lrt` 与 `web`。
   - 流程依据 psd2live-examples（CC0）的公开手册，提示词见第 8 轮交接文档。
   - 播放器版本必须和导出模型的 PSD2Live 版本一致：更新模型时，从同一次 `web` 导出里替换 vendor 的两个文件。
6. **兼容**：`rig` 与 `video` 渲染器保持不变。B3 在 p2l 模型通过审核前，继续使用 rig 包。

## 备选方案

- **继续修 0007 的部件平移**：7 轮证明有天花板，用户已否决"降低视差幅度"的折中。
- **自写网格变形运行时**（单图 + 穹顶位移，已做小样，8 个姿势零瑕疵）：
  - 头部转动效果好，但只有一张图，无法表现眨眼时眼睑下的虹膜、张嘴的口腔、抬臂时的袖窿等需要"新内容"的动作；
  - 物理、表情、动作编辑都要从零写，工作量和质量都不如成熟方案。
- **mesh-avatar-studio（MIT）**：思路相同，面向头肩像，不支持抬臂和全身动作。
- **livliv player（Apache）**：模型只能在其商业平台制作，自带角色禁止商用。
- **Live2D Cubism / Spine / DragonBones 运行库**：授权冲突，红线。

## 后果

- 正面：
  - 转头、歪头、抬臂时只拉伸不错开，从结构上消除"露底"问题。
  - 眨眼、呼吸、视线、物理由成熟运行时提供。
  - 美术交付变成"一份分层 PSD"，以后换装、新角色都走同一管线。
- 代价：
  - 渲染进程包增加约 0.9 MB（wasm 内联后）。
  - 宠物窗口改用 WebGL。
  - 引入一个外部工具（PSD2Live 编辑器）进美术管线。
  - 播放器跟随上游版本更新。
- 风险：
  - 上游项目较新（2026 年），运行时格式可能变化。用"播放器与模型同源"规则和 vendor 的 hash 记录控制。
  - 序列帧大动作（dance/sit 等）在 p2l 渲染器下暂不支持叠加精灵图，先回退到 Idle。是否需要叠加，等 B3 模型的动作清单定下再议。
- 待验证：
  - Electron 中 WebGL 透明窗口的点击检测和 CPU 占用（目标待机 ≤5% 单核，与 0007 相同）；
  - 拿到 B3 模型后，在 Mac 上实测。
