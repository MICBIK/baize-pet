# ADR 0007: 角色渲染采用分层部件与程序动画

- 状态：已接受（2026-11-04）
- 决策人：haiden（2026-11-02 拍板）

## 背景

逐帧生成的序列帧/webm 路线存在三个结构性问题：

1. **跳帧**：每动作 5~8 帧，8fps 播放一格一格跳。
2. **闪烁**：每帧独立生成，头发/袖口/脸的位置逐帧漂移，换帧时"闪"；补帧只会更闪。
3. **比例漂移**：每条动作头身比不同，切换动作时角色忽大忽小。

## 决定

- 默认角色改为**分层部件 + 程序动画**（2D cutout rig，运行时全自研，无第三方动画运行库）：
  - 只生成一张高质量标准像（master），拆为 23 个部件图层，60fps 程序驱动呼吸/眨眼/扫视/视线跟随/耳抖/尾摆/口型/挤压回弹。
  - 表情靠替换眼/嘴/三眼插槽（18 个预设）；手臂/眼/嘴/三眼为插槽部件。
  - 少数大动作（dance/sit/sit-idle/hide-in-hood）继续用已归一化的序列帧图集，与 rig 共用双锚点（兜帽宽 92px、脚底 y=246，256 窗口坐标系）。
- `manifest.renderer` 新增 `"rig" | "video"`（缺省 video）：video 包（placeholder）继续走原 `<video>` 路径，行为逐字不变；rig 包由 RigPlayer 按 rig.json 驱动。
- 角色包 schema 支持三种动画值形式：`rig:<clip>`、`sprite:<sheet>`、普通文件路径（video）。

## 备选方案

- **继续补帧**：只缓解跳帧，不解决闪烁与比例漂移；生图成本线性增长。
- **3D/VRM**：表现力更强，但美术与工程成本数量级上升，且与当前平涂 chibi 风格不符。
- **Live2D Cubism / Spine / DragonBones 运行库**：授权与 AGPL-3.0-only 冲突或不可再分发，红线禁止。
- **WebGL 网格变形**（Live2D 式网格弯曲）：表现力上限更高，作为未来演进方向保留；当前 Canvas2D 仿射 + 插槽替换已满足"丝滑、大小一致、表情丰富"的验收目标。

## 与 ADR 0004 的关系

ADR 0004（占位动画 VP9 alpha 生成管线）将 webm 确立为当时的统一动画格式；本决定**有意偏离**它：webm/video 渲染器保留为兼容路径（placeholder 包继续可用），但默认角色改为 rig + 序列帧图集混合渲染。偏离原因即背景中的三个结构性问题；0004 的生成管线本身（tzcode.top API、alpha 校验等）在美术管线中继续沿用。

## 后果

- 待机时任意时刻"活着"：60fps 程序层（呼吸/眨眼/扫视/跟随）持续叠加，无跳帧与闪烁。
- 所有动作共享同一 master 比例：切换动作不再忽大忽小（双锚点对齐序列帧）。
- 表情组合爆炸：18 预设 × 任意动作，插槽级复用；新增表情只需一张"只改眼/嘴"的重绘图。
- 新增源文件：`packages/rig`（纯 TS、DOM-free、126+ 单测）、`apps/desktop .../pet/`（RigPlayer/SpritePlayer/VideoPlayer/hitTest）、`tools/rig-pipeline/`（可复现美术管线）、`characters/baize-b3`（首个 rig 包）。
- 代价：parts/rig.json/表情贴片的美术管线一次到位的复杂度（本轮已建成）；运行时 CPU 预算待实测（目标待机 ≤5% 单核）。
