# ADR 0006：生产构建端到端冒烟测试（Playwright `_electron` + xvfb）

- 状态：已接受 · 2026-10-27

## 背景

M0-M4 骨架单测全绿，但审核方在无头 Electron 中实际运行生产构建后发现三处核心流程断裂（协议污染 canvas 导致宠物无法点击、渲染层多入口未打包、向导测试连接必败）。单元测试按模块 mock 依赖，覆盖不到"主进程 + preload + 渲染层 + 自定义协议 + 打包产物"的集成路径。需要一道针对**生产构建**（`pnpm build` 后的 `apps/desktop/out/`，而非 dev server）的端到端冒烟防线。

## 决定

- **测试入口**：`apps/desktop/tests/smoke/run.mjs`，Node 直跑脚本（`pnpm test:smoke`），断言失败以非零码退出；不接入 vitest，避免 E2E 混入单测覆盖率和 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 的质量任务。
- **驱动方式**：Playwright 的 `_electron` API（依赖 `playwright-core`，无浏览器下载、无 postinstall）。相比自写 Electron 测试入口，能直接拿到每个 `BrowserWindow` 对应的 Page，做 DOM 断言与 `page.evaluate`（含经 contextBridge 暴露的 `window.baize` IPC）。
- **贴近真实安装的启动**：以**应用目录**（`apps/desktop`，走 package.json `main` 字段）而非 `out/main/index.js` 文件启动——后者会使 `app.getAppPath()` 指向 `out/main`，破坏 characters 根目录等基于 appPath 的解析。
- **用户数据隔离**：Electron 45 支持 `--user-data-dir=<临时目录>`，`app.getPath('userData')` 整体重定向，config.json 与 memory.sqlite 全部落进临时目录（测试后删除），绝不触碰真实用户档案。附带 `--password-store=basic` 保证无钥匙串环境（Linux CI）下 safeStorage 可用。
- **模型服务 mock**：`tests/smoke/mock-openai.mjs` 用 `node:http` 实现 OpenAI 兼容的 `/v1/chat/completions` SSE 流式端点，记录每个请求的 Authorization 与 URL。向导 draft 指向 mock 地址（`127.0.0.1`，属 07 出网白名单中"用户显式配置的端点"）。
- **CI 接入**：`ci.yml` 新增 `smoke` 任务（ubuntu-latest）：`pnpm build` → `xvfb-run -a pnpm test:smoke`。该任务**不设** `ELECTRON_SKIP_BINARY_DOWNLOAD`（需要真实 Electron 二进制）；Linux 下 Electron 追加 `--no-sandbox`（GitHub runner 的 user namespace 配置不保证 Chromium 沙箱可用）。
- **断言清单**（即本轮 P0 的回归防线）：`out/renderer/` 三页 html 存在；三个窗口加载完成且全程无 `did-fail-load`；宠物 `<video>` → canvas 中心像素 `getImageData` 不抛异常且 alpha > 0；向导测试连接的请求带 `Authorization: Bearer <draft key>` 且命中配置的 baseUrl；保存后磁盘无明文 key（红线断言）；发消息收到流式回复；memory.sqlite 新增语义事实与情景记录。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 自写 Electron 测试入口（主进程包装器） | 需要自行实现窗口枚举、页面注入与输入合成，重造 Playwright 已有能力 |
| 对 dev server 做 E2E | 无法暴露打包类缺陷（本轮 P0-2 正是"构建产物缺文件"），与审核发现路径不符 |
| vitest 集成（`vitest --pool=forks` + xvfb） | 拉长质量任务时长、混淆覆盖率统计；Node 脚本足够且失败信息更直白 |
| macOS runner 上跑冒烟 | 需要签名/权限等额外处理；07 的 CI 约定 ubuntu 优先，macOS 真机验收由负责人执行 |

## 后果

- 每个新增 `window.baize` IPC、页面或打包入口都应考虑在 `run.mjs` 补一条断言；冒烟套件是 P0 级回归的唯一自动防线。
- CI 每次运行多下载一份 Electron 二进制（约 100 MB）并多跑约 1-2 分钟，换取生产构建可用性的保证。
- `--user-data-dir` 的重定向行为是 Electron 层保证，与应用代码解耦；若未来 Electron 移除该开关，需在应用内提供等价的 userData 覆盖入口（届时写 ADR）。
