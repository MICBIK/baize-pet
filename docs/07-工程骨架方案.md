# 07 - 工程骨架方案

> 状态：v1 · 2026-10-26 · 供执行骨架搭建的负责人（人或 AI）使用。产品与架构依据见 [00](00-产品定义.md)、[02](02-功能规格与路线图.md)、[03](03-架构设计.md)、[04](04-记忆系统设计.md)。

## 1. 目标与范围

**目标**：在 macOS（Apple Silicon）上跑起一个"能看见、能拖动、能聊天、会记住"的最小桌宠骨架，工程结构按长期项目设计，后续功能可以按包逐步加入。Windows 在 CI 中保持可构建，但不要求功能完整。

**本轮范围（M0-M4）**：

| 里程碑 | 内容 |
|---|---|
| M0 | 仓库工程化：monorepo、TypeScript、代码规范、测试、CI、SPDX 头 |
| M1 | 桌宠窗口：透明置顶、鼠标穿透、拖拽、播放透明 webm 动画、托盘菜单 |
| M2 | 核心包：事件总线、行为选择器（加权随机）、情绪状态、角色包加载 |
| M3 | 记忆引擎基础版：SQLite schema、写入 / 检索、导入 / 导出 |
| M4 | 对话：LLM 适配器、模型配置向导、API key 安全存储、对话气泡 UI，并把记忆接进对话 |

**不在本轮范围**：语音、bot 渠道、agent hooks、睡眠整理与遗忘退化、台词池的 LLM 生成、画像页、Windows 专属功能、正式美术资源。这些在后续轮次单独规划。

## 2. 技术选型（已定，不要更换）

| 项 | 选型 |
|---|---|
| 运行时 | Node.js 22 LTS，pnpm 9（`packageManager` 字段锁定版本） |
| 语言 | TypeScript，`strict: true` |
| 桌面框架 | Electron（当前稳定版）+ electron-vite（开发与构建）+ electron-builder（打包） |
| 渲染层 | React + Vite；动画用 `<video>` 播放 VP9-Alpha webm |
| 存储 | better-sqlite3 + sqlite-vec |
| 校验 | zod（角色包 manifest、配置、导出格式） |
| 测试 | Vitest（core 包要求单测）；Playwright 可选，用于 Electron 冒烟测试 |
| 代码规范 | Biome（lint + format，一个工具搞定） |
| LLM | `openai` SDK（配置 baseURL 覆盖 DeepSeek / GLM / Kimi / Ollama 等 OpenAI 兼容服务）+ `@anthropic-ai/sdk` |

选型或版本有疑问时，在 `docs/adr/` 新增一条 ADR 说明，不要直接替换。

## 3. 目录结构

```
baize-pet/
├── apps/
│   └── desktop/                 # Electron 应用（main / preload / renderer）
│       ├── src/main/            # 窗口、托盘、IPC、存储路径、安全存储
│       ├── src/preload/         # contextBridge 暴露的最小 API
│       ├── src/renderer/        # React：宠物层、对话气泡、设置 / 向导
│       └── electron-builder.yml
├── packages/
│   ├── core/                    # 纯 TS，不依赖 Electron：事件总线、行为、情绪、角色包
│   ├── memory/                  # 记忆引擎：SQLite schema、record / recall / export / import
│   ├── llm/                     # 供应商适配器与能力协商
│   └── shared/                  # 类型、常量、zod schema
├── characters/
│   └── placeholder/             # 占位角色包（程序生成的简单动画，非正式美术）
├── docs/                        # 产品与设计文档（00-07）+ adr/
├── assets/                      # 资产许可（CC BY-NC-SA 4.0 + NOTICE）
├── .github/                     # CI、CLA、issue / PR 模板
├── LICENSE                      # AGPL-3.0
└── package.json / pnpm-workspace.yaml / tsconfig.base.json / biome.json
```

依赖方向：`apps/desktop → packages/*`，`packages/memory`、`packages/llm` → `packages/shared`，`packages/core` 不依赖 `memory` / `llm` 的实现，只依赖 `shared` 中的接口。

## 4. 各里程碑细则与验收标准

### M0 仓库工程化

- pnpm workspace、`tsconfig.base.json`、Biome、Vitest 配好；根目录 `pnpm dev / build / test / lint / typecheck` 可用。
- 每个源文件头：`// SPDX-License-Identifier: AGPL-3.0-only`，加一个脚本在 CI 中检查。
- GitHub Actions：
  - `ci.yml`：push / PR 时在 ubuntu 上跑 lint、typecheck、test。
  - `release.yml`：推送 `v*` tag 时，在 `macos-14`（arm64）和 `windows-latest` 上构建，产物上传到 GitHub Release（draft）。
  - macOS 产物不做公证，但必须能在 Apple Silicon 上启动（确认经过 ad-hoc 签名，用 `codesign -dv` 在 CI 中验证）。
- **验收**：新开 PR 时 CI 变绿；打一个测试 tag 能拿到 `.dmg` 和 Windows 安装包。

### M1 桌宠窗口

- 主窗口：`transparent`、`frame: false`、`hasShadow: false`、`alwaysOnTop`（层级用 `floating` 或更高，确保在普通窗口之上）、`skipTaskbar`、在所有桌面空间可见。
- 鼠标穿透：默认 `setIgnoreMouseEvents(true, { forward: true })`；渲染层根据鼠标所在位置是否落在宠物不透明区域（用 canvas 取 alpha 或用包围盒）切换是否可点。
- 拖拽宠物移动窗口，记住上次位置；多显示器下位置合法。
- 播放占位角色包的 `idle` / `click` / `drag` 动画，缺失动作回退到 `idle`。
- 托盘（Mac 菜单栏）菜单：显示 / 隐藏、勿扰、设置、退出。隐藏时暂停视频与渲染循环。
- 占位动画：用 ffmpeg 等工具程序生成透明背景的简单图形动画（VP9 + `yuva420p`），并在 `characters/placeholder/README.md` 写明生成命令。
- **验收**：Mac 上宠物悬浮在所有窗口之上；宠物以外的透明区域可以点到下面的应用；可拖动；点击切换动画；托盘可隐藏和退出。

### M2 核心包

- 事件总线：`{ source, type, payload, timestamp }`，支持订阅 / 取消订阅，订阅者异常不影响其他订阅者。
- 行为选择器（见 [03 §3.3](03-架构设计.md)）：
  - 规则识别场景 → 候选动作列表 → 按 `效用 = f(情绪, 时段, 最近事件, 冷却, 重复惩罚)` 打分 → **按分数加权随机抽取**（softmax，温度参数外置）。
  - 随机数源可注入（带种子），以便单测复现。
  - 打断优先级：用户拖拽 > 对话 > 自发行为。
  - 台词：本轮使用角色包内的预置台词池，按场景随机抽取；接口预留给后续的 LLM 台词池。
- 情绪状态：开心 / 无聊 / 生气 / 思念 向量，随时间衰减、随交互累加；参数来自角色包。
- 角色包加载：用 zod 校验 `manifest.json`（名称、版本、动作 → 文件映射、人设参数、预置台词、LICENSE 是否存在），校验失败给出可读错误。
- **验收**：`packages/core` 单测覆盖率 ≥ 80%；同一场景重复触发 100 次，动作分布符合权重、且不会连续重复超过冷却规则允许的次数。

### M3 记忆引擎基础版

- 按 [04](04-记忆系统设计.md) 建表：工作记忆（内存）、语义记忆、情景记忆（含 event_type / emotion_tags / topic_tags / importance / decay_state / pinned / embedding）、程序性记忆；带 schema 版本号与迁移机制。
- 实现 `MemoryEngine` 接口中的 `record`、`recall`（标签 + 时间 + importance 粗筛；向量检索先留接口，embedding 模型下一轮接入）、`quickContext`、`exportAll`、`importAll`。
- 导出格式：单个 JSON（带 `format: "baize-memory-export"`、`version`、导出时间）+ 可选直接拷贝 SQLite 文件；导入前校验版本并备份当前库。
- 数据目录：Electron `app.getPath('userData')` 下，路径集中在一处管理。
- **验收**：单测覆盖导出 → 清空 → 导入后数据完全一致；设置页有"导出记忆 / 导入记忆 / 清空记忆"三个按钮且可用。

### M4 对话

- `packages/llm`：统一的 `chat(messages, options)` 流式接口；适配器两类：OpenAI 兼容（预置 DeepSeek、GLM、Kimi、MiniMax、Ollama 的 baseURL 模板）与 Anthropic。能力声明（是否支持流式 / 工具调用 / 图片）。
- 模型配置向导（首次启动自动出现，设置页可重进）：选厂商 → 打开该厂商获取 key 的页面 → 粘贴 key → 测试连通 → 完成。本轮用简单的 UI 即可，引导动画后续由美术补上。
- API key 用 Electron `safeStorage` 加密后存储（Mac 上由 Keychain 保护），不得明文写入配置文件或日志。
- 用户可设置单日 token 上限，超出后停止调用并提示。
- 对话 UI：点击宠物或快捷键打开输入框，回复以气泡流式显示；人设 system prompt 来自角色包 `persona.md` + `quickContext()`。
- 每轮对话后写入情景记忆；对话中提到的明确事实（名字、偏好）做轻量抽取写入语义记忆。
- 起名仪式：首次对话询问用户名字并请用户给宠物起名，写入语义记忆并作为第一条情景记忆。
- **验收**：配好 DeepSeek（或任一 OpenAI 兼容服务）后能流式对话；重启应用后宠物记得用户的名字和自己的名字；断网或 key 错误时给出友好提示且不崩溃。

## 5. 工程约定

- **不要复制其他 AGPL / GPL 项目的代码**（如 clawd-on-desk），只可参考思路。第三方依赖登记到 `THIRD_PARTY_NOTICES.md`。
- 所有出网请求只发往用户配置的模型服务和 GitHub Releases 更新检查，**没有任何遥测**。
- 动画"捣蛋"只做视觉效果，不触碰真实文件与窗口（[00 §5.4](00-产品定义.md)）。
- 提交信息用 Conventional Commits；每个里程碑一个 PR，PR 描述写明验收标准的检查结果。
- 文档用中文；代码标识符和注释用英文。
- 实现中发现文档有矛盾或无法实现之处：记录到 `docs/open-questions.md`，按最保守的方案先实现，不擅自更改产品决策。
