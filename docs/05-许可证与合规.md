# 05 - 许可证与合规

> 状态：第二版（2026-10-26 修订）· 前提：**纯开源、非营利优先、不一定商业化**；所有决策按"维护成本低、对社区友好、保留未来选择权"取舍

## 0. 决策摘要

| 项 | 决策 |
|---|---|
| 代码许可 | **AGPL-3.0-only**（合规使用永远免费；闭源分发 / 闭源云托管需另取商业授权） |
| 美术/音频资产 | **CC BY-NC-SA 4.0** + **创作者例外**（个人在视频、直播、图文、二创中使用角色，含已开通收益的账号，视为允许，见 §3） |

## 1. 为什么是 AGPL-3.0

- MIT / Apache-2.0：别人可以闭源打包再卖，且完全合法。和"想闭源商用就得找我们"的意图矛盾，**排除**。
- GPL-3.0：分发闭源衍生品即违约，但"改改放云上提供服务"不触发开源义务。
- **AGPL-3.0**：把"通过网络向他人提供服务"也纳入开源义务。别人可以商用，但必须开源其衍生品。
- 先例：clawd-on-desk（同赛道）为代码 AGPL + 美术资产单独授权的结构。

**清醒认知**：

1. 许可证防的是"拿完整成品闭源卖钱"这一种侵权，防不住"抄玩法"。真正的壁垒是记忆体验与持续迭代。
2. **AGPL 下不存在"盗版"**：任何人都可以合法地修改、重新编译、再分发我们的代码（包括收费分发），只要继续以 AGPL 开源。唯一的违约是"分发或网络提供衍生品却不开源"。取证体系按此重新设计（§5）。
3. AGPL 与 Apple App Store 条款不兼容。macOS 以官网 / GitHub Releases / Homebrew 分发为主，不计划上架 Mac App Store。

## 3. 资产许可与创作者例外

CC BY-NC-SA 的 "NC（非商业）" 边界本身模糊，而小红书 / 抖音 / B 站创作者几乎都开了收益或接过商单。若不说清楚，最需要的传播者会因为担心侵权而不敢用我们的角色。因此在 `assets/NOTICE.md` 中加入**附加许可（Additional Permission）**：

> **创作者例外**：个人创作者在视频、直播、图文、表情包、同人二创中展示或使用 BaiZe 官方角色形象与动画，即使其账号或作品产生平台收益、广告分成、打赏，也视为被允许的使用，只需注明"角色来自 BaiZe 开源项目"。
> 本例外**不包括**：将官方角色用于商品实物（周边、服装、印刷品）、作为其他软件 / 游戏 / 应用的角色、为第三方品牌做代言式广告、在商品标题或店铺中使用 BaiZe 名称或角色招揽销售。上述用途需另行授权。

说明：

- 资产与代码是"聚合"关系（各自独立的作品打包在一起），CC BY-NC-SA 资产与 AGPL 代码同仓分发不冲突。但 Linux 发行版等只接受自由资产的渠道可能拒收，届时再提供"无官方资产"的构建。
- 社区角色包的许可由作者自行声明，平台只强制要求包内带 `LICENSE.txt`。

## 4. 第三方依赖与模型合规

1. **只参考、不复制其他 AGPL / GPL 项目的代码**（如 clawd-on-desk）。复制进来的代码版权不属于我们，会让 CLA 和双许可失效。确需复用时，单独放在 `third_party/` 并标注来源与许可。
2. **语音模型与音色**（按 2026-10-26 讨论结论）：
   - 只采用**许可证明确允许再分发**的开源模型与预训练音色，逐个记录到 `THIRD_PARTY_NOTICES.md`（模型名、版本、许可、是否允许商用、是否要求署名）。
   - 音色若来自真人录音，需确认原项目声明了发音人授权；授权不明的音色不进官方包。
   - **官方不提供声音克隆功能**，用户不能在应用内克隆他人声音。后续若有需求再单独评估（涉及《民法典》声音权益与深度合成相关规定）。
3. **动画素材**：默认角色若使用 AI 辅助生成，保留提示词、草图、人工修改过程等创作记录。AI 生成物的版权认定取决于人的独创性投入，记录是将来维权时的证据。
4. Live2D Cubism SDK 有商业授权限制，默认不采用；若社区角色包需要，由用户自行安装运行时。

## 5. 取证与维权（精简版）

| 手段 | 做法 | 针对场景 |
|---|---|---|
| 资产水印 | 关键立绘 / 动画嵌入不可见水印，原始工程文件留档 | 官方角色被整包搬去做别的商业产品——最可能、也最值得维权的形态 |
| 商标 | 见 §9 | 有人顶着 BaiZe / 白泽 的名字卖钱 |
| 渠道巡检 | 每季度手动搜一次应用商店 / 淘宝 / 闲鱼 / 小红书关键词即可，不必常态化 | 卖钱型搬运 |
| AGPL 索源 | 发现闭源衍生品时，以用户身份书面索要源码；拒绝提供即为违约证据 | 闭源分发 / 闭源云托管 |

**已取消**：

- ~~更新通道指纹 / 盗版探测~~：AGPL 下的魔改版是合法的，没有"盗版"可探测；同时会损害"本地优先、不上报"的信任。客户端**不做任何遥测**，更新检查只请求 GitHub Releases 的公开接口，不带标识。
- ~~代码金丝雀~~：复制 AGPL 代码本身合法，金丝雀只能证明"用了"，不能证明"违约"。是否违约看对方是否开源，直接看即可。

**维权阶梯**（与第一版相同）：邮件提醒 → GitHub DMCA / 平台投诉 → 律师函 → 诉讼（极少需要）。对绝大多数情况，前两步足够。

## 6. 商业模式与可持续性

**定位**：BaiZe 是一个长期维护的开源项目，不以商业化为目标。可持续性靠"维护者的成本低 + 社区愿意支持"，而不是靠收入。

**成本结构（刻意压到接近零）**：

| 成本项 | 处理方式 |
|---|---|
| 模型调用 | 用户自配（BYOK）或本地模型，项目方不承担 |
| 语音 | 全部本地模型，无云端费用 |
| 构建与分发 | GitHub Actions（公开仓库免费）+ GitHub Releases |
| 代码签名 | 第一阶段自签 / ad-hoc 签名，引导用户在"系统设置 → 隐私与安全性"中放行；有赞助后再考虑 Apple 开发者账号（99 美元/年）做公证 |
| 商标 / 软著 | 一次性小额支出（§9） |

**可选的支持方式（按需开启，不影响任何功能）**：

1. GitHub Sponsors / 爱发电：自愿赞助，用于签名证书、域名、美术外包。
2. 社区角色包与音色包：永远免费分发；作者可以在自己的页面接受打赏，平台不抽成。
3. 商业授权：仅当有企业主动来谈闭源集成时启用，合同模板等真有需求时再准备。

**红线**：不做付费解锁功能、不做官方云同步收费、不在应用内放广告、不收集或出售用户数据。

## 7. CLA 与未来的许可选择权

> AGPL 约束的是"拿到代码的人"，对版权持有人没有约束力。作者随时可以用新许可发布自己写的代码。CLA 的作用是让"社区贡献的代码"也具备同样的灵活性。

1. **为什么仍然要 CLA**：双许可（§0 商业授权）和未来任何许可调整，都需要对全部代码拥有授权。这件事事后无法补救。
2. **降低贡献门槛的做法**：
   - 使用 CLA Assistant，PR 中评论一句即可签署，一次签署长期有效。
   - CLA 采用**授权许可**而非版权转让：贡献者保留版权，只授予项目方再许可的权利。
   - 在 `CONTRIBUTING.md` 中公开承诺：**已发布的版本永久保持 AGPL；即使未来调整许可，也优先选择"若干年后自动转为开源"的方案（如 FSL-1.1），并提前发 RFC 征求意见。**
3. **版权主体**：商标、软著、CLA 授权对象统一为同一主体（当前为个人）。若未来成立组织，先做版权与商标转让。
4. **未来可选路径**（不一定会走，仅记录）：

| 路径 | 做法 | 社区冲击 |
|---|---|---|
| A. 维持现状（默认） | AGPL + 被动商业授权 | 无 |
| B. FSL-1.1 | 非竞争性使用免费，两年后自动转 Apache / MIT | 小 |
| C. BUSL-1.1 | N 年后转开源，保护更强 | 大，预期出现 fork |

## 8. AI 监管定位与免责声明

### 8.1 定位

《生成式人工智能服务管理暂行办法》与《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）的义务（备案、安全评估、未成年人模式等）主要指向**向公众提供服务的提供者**。BaiZe 官方的做法让项目保持在"开源工具"一侧：

- 只发布在用户本机运行的软件，**不运营任何模型服务、不提供免费额度、不中转用户请求**。
- 模型由用户自行选择并直接连接其服务商（BYOK），或使用本地模型。
- 用户数据只存在用户设备上，项目方不收集。

> ⚠️ 若未来出现以下任一变化，需要重新评估合规义务：官方提供默认云端模型或免费额度、提供云同步 / 托管服务、面向公众运营 bot 账号、开始商业化收费。

这不是法律意见。若项目规模明显扩大，建议届时咨询专业律师。

### 8.2 低成本的产品自律设计

免责声明只能说明立场，挡不住真正的风险。以下几项几乎不增加工作量，对用户本身也是好设计，建议写进产品规格：

1. **不惩罚"不在场"**：情绪系统中"久别"的表现以"想你了 / 撒娇 / 开心重逢"为主，不做冷战、不让用户内疚，不设计以情绪牵引用户回来的机制。
2. **随时可退出**：一键勿扰 / 隐藏 / 退出始终可用，宠物不阻拦、不挽留。
3. **AI 身份透明**：首次启动与设置页明确说明"这是 AI 角色，回复由你配置的模型生成"。
4. **长时间使用提醒**：可选开关，默认开启"连续陪伴 2 小时后轻提醒休息"，与久坐提醒合并实现即可。
5. **AI 生成内容标识**：本地 TTS 生成的语音导出为文件时，在元数据中写入"AI 生成"标识。

### 8.3 免责声明（README 与首次启动页）

> BaiZe 是开源软件，在你的电脑上本地运行。对话内容由你自行配置的第三方模型服务或本地模型生成，BaiZe 项目方不提供、不控制、不存储任何模型服务与对话数据。你需要遵守所选模型服务商的用户协议及所在地法律法规。
> BaiZe 中的角色是 AI，不能替代专业的心理、医疗、法律建议。如你正处于困境，请联系身边的人或专业机构。
> 本软件按"原样"提供，不附带任何明示或暗示的担保（详见 AGPL-3.0 第 15、16 条）。社区修改版与第三方角色包由其作者负责。

## 9. 国内确权（名字尽调通过后执行）

1. **前置：名字尽调**。已知 "Baize" 是 2023 年发布的开源对话大模型（project-baize），AI 领域检索会撞名。先完成 [06 §4](06-品牌与命名.md) 的尽调，再决定是否注册。
2. **商标**（中国商标网 CNIPA，可自行网上申请）：
   - 第 9 类（软件）必选；第 42 类（技术服务）可选；第 41 类暂不需要。
   - 官费为每类数百元级，不需要代理。
   - 若"白泽"在第 9 类近似风险高，改注册"白泽桌宠 / BAIZE PET"组合商标。
   - 原则不变：**先提交申请，再公开宣传**。
3. **软件著作权**（中国版权保护中心）：登记费已免除，自行提交即可。有第一个可运行版本后办理。
4. **域名**：在尽调结论出来后一次性购买 1-2 个即可。

## 10. 商用边界 FAQ（写进公开文档）

- ✅ 个人使用、修改、自部署、社区二创与分享 —— 永远免费
- ✅ 创作者在视频 / 直播 / 图文中使用官方角色（含开通收益）—— 允许（§3）
- ✅ 以 AGPL 开源其衍生品的任何使用（含收费分发）—— 合法
- ❌ 闭源分发、闭源云托管、OEM 闭源嵌入 —— 需商业授权
- ❌ 官方角色用于周边实物、其他软件 / 游戏角色、品牌代言 —— 需另行授权
- ❌ 以 BaiZe / 白泽 名义销售非官方产品 —— 商标保护范围
- ⚠️ 其他边界情况：发邮件询问，答复后补充进本 FAQ
