# 00 - 产品定义

> 状态：已定稿待评审 · 2026-10-26

## 1. 一句话定位

**BaiZe 是一只有灵魂的 AI 桌宠**——它不是一个"会动的贴纸"，而是"个人 Agent 的脸"：

```
感知层（系统事件 / agent hooks / 传感器）＋ 决策层（LLM + 行为规则）＋ 执行层（通知 / 语音 / IPC / UI 自动化）
```

桌宠的可爱外壳之下，是一个完整的个人 Agent。用户看到的永远是那只宠物，宠物背后做所有的事。

## 2. 为什么做 / 市场判断

1. **赛道正在换挡**：桌宠从"怀旧贴纸"向"AI Agent 伴生体"跃迁（clawd-on-desk 6.5k 星、dsh-pet 4.3k 星、量子位报道 DeepSeek 插件生态里桌宠类是爆火主力）。窗口期已开，但尚无产品同时做好"壳"与"芯"。
2. **现有产品的断层**（详见 [01-竞品调研](01-竞品调研.md)）：交互最好的没有 AI；AI 全的没有桌面轻量感；Agent 联动好的不能对话。**四者交集为空**。
3. **普通人市场是空的**：现有开源竞品全是开发者向（配 key、命令行）。Desktop Mate 在 Steam 卖爆证明普通用户愿意为"桌面上有个伴"付费，而免费开源的我们只要求他们"下载即可用"。

## 3. 目标用户

| 阶段 | 人群 | 诉求 |
|---|---|---|
| 冷启动（前 1000 用户） | 小红书 / B 站"赛博宠物爱好者" | 情绪价值、可爱、可晒、可二创 |
| 成长期 | 普通电脑用户 | 开箱即用的陪伴、提醒、轻效率 |
| 并行 | 开发者 / Agent 重度用户 | Agent 状态联动、代传话、代操作 |

冷启动人群对早期毛糙容忍度高且自带传播力；开发者功能是口碑与技术声望来源；普通人市场是终局。

## 4. 差异化主张（护城河排序）

1. **记忆与性格体验**（最核心）：分层记忆 + 遗忘 + 性格随时间演化。用得越久越离不开，时间沉淀出的壁垒，竞品无法用一次功能更新追平。
2. **自主行为的"灵魂感"**：效用驱动的行为选择（非随机点播）、情绪系统、与真实工作状态联动。
3. **语音**：可打断的自然对话（barge-in）+ 口型同步。
4. **代操作**：从状态感知到官方通道传话再到 UI 代操作，逐档解锁。

## 5. 设计原则（红线与铁律）

1. **本地优先**：记忆、人设、对话历史默认只存在用户设备。云端模型是可选组件，不是架构前提。
2. **检索永不阻塞回复**：回复先基于工作记忆 + 语义记忆（毫秒级），情景记忆异步补充，下一句自然引用（"对了，我想起来了……"）。慢检索被包装成拟人化 feature。
3. **生气要有台阶**：情绪系统服务于留存。生气分级、可哄好、有自动恢复脚本——宁可拟人不真实，不可把用户劝退。
4. **动画假象红线**：所有"捣蛋"行为（扒拉图标、移动物品）必须是叠加渲染的视觉假象，绝不触碰真实文件系统与窗口状态。
5. **角色与人设分离**：形象、人设、动作库打包为"角色包"资源，平台与角色解耦（详见架构文档）。
6. **接口与数据格式永远开放**：无论核心模块未来是否开源，记忆的存储格式、导出规范、插件接口永远公开。"你的记忆永远可导出"是隐私承诺的底线。
7. **合规姿态先行**：官方项目不碰个人微信逆向协议等灰色地带；社区二开自担其责并明确声明。

## 6. 非目标（Non-goals）

- 不做多租户云托管版（记忆上云的 SaaS）——与本地优先原则冲突；商业授权谈判除外。
- 不做个人微信个人号的逆向接入。
- 不做通用桌面自动化框架——代操作只是执行层的一个可插拔通道，且有白名单与确认机制。
- MVP 阶段不做移动端。

## 7. 已定决策摘要

| 决策点 | 结论 |
|---|---|
| 形象来源 | 自设计默认角色（不用 DeepSeek 鲸鱼娘——社区同人、版权悬置），架构支持社区角色包 |
| 项目名 | **BaiZe（白泽）**，与创始人姓氏关联 |
| 开源策略 | 全部开源、不以商业化为目标：代码 AGPL-3.0（闭源商用需商业授权，被动选项），资产 CC BY-NC-SA + 创作者例外；可持续性靠自愿赞助（详见 [05 §6](05-许可证与合规.md)） |
| 防护策略 | 放弃核心闭源；只保留资产水印 + 商标/软著（名字尽调后办理）；客户端不做任何遥测 |
| 核心壁垒的清醒认知 | 承认 80% 可被复刻，记忆系统的体验深度是唯一长期壁垒，靠迭代速度拉开 |
| 人设策略 | 出厂内置 3-4 套预设人格种子（治愈 / 傲娇 / 捣蛋 / 知性方向），用户可基于预设自定义 |
| 模型接入 | 多供应商接口聚合：GPT / Claude / DeepSeek / GLM / Kimi / MiniMax / 小米 MiMo / 本地 Ollama，想用哪家就用哪家；**第一阶段无默认模型**，以引导动画带用户自配 key |
| 技术栈与平台 | Electron + TypeScript；**先 macOS，再 Windows**（详见 [03 §2](03-架构设计.md)） |
| 语音 | 全本地运行、零云费；默认全局监听 + 唤醒词，可选快捷键触发；不提供声音克隆 |
| 贡献者协议 | CLA 自第一天启用（为未来换许可 / 闭源化保留全部权利，详见 [05 §7](05-许可证与合规.md)） |
| 冷启动渠道 | GitHub + Gitee 镜像 + linux.do（开发者口碑）+ 小红书 / 抖音（赛博宠物内容营销） |

## 8. 开放问题（已于 2026-10-26 第二轮评审裁决）

| 原开放问题 | 裁决 |
|---|---|
| 默认角色人设方向 | 不押单一风格：出厂 3-4 套预设人格种子 + 用户自定义（人设参数外置） |
| 默认云端模型 | 不设唯一默认：多供应商接口聚合，用户贴 key 自选（Claude / GPT / DeepSeek / GLM / Kimi / MiniMax / MiMo / Ollama） |
| 冷启动发布形态 | 双轨并行：GitHub + Gitee + linux.do 吃开发者口碑，小红书 + 抖音吃赛博宠物人群 |
